# حالة CodeQL العامة الفارغة وإثبات حالة النسخة

> استعمل المالك النسخة v4 وأكمل تطبيق القرارات الـ11. تؤكد بوابة GitHub النجاح؛
> [إيصال التطبيق ودمج المصدر](DELIVERY-2026-11-06-AR.md). الأوامر أدناه توثق
> الإجراء الذي نُفذ قبل الدمج، ويتوقف حارس الأداة إذا أعيد تشغيلها بعد إغلاق PR29.

أكد ناتج المالك أن الأرقام والقاعدة والأداة متطابقة لجميع الأهداف الـ11، لكن
ستة تنبيهات تعيد `state: null`: 243 و245 و246 و247 و248 و260. الحالات الخمس
الأخرى تعيد `open`. وبقراءة #243 مباشرة ثبت أن حالته العامة null، بينما
`most_recent_instance.state` وinstance الخاصة بـ`refs/pull/29/head` كلاهما
`open`، عند المصدر `1355b12`. لذلك كانت الأداة تتوقف عند أول حالة فارغة بعد
نجاح القراءات الأربع الأولى. سجل محاولة المالك كان في مرحلة preflight مع
`decisions: []`، فلا توجد كتابة في تلك المحاولة.

حُفظت [بيانات المالك](evidence/codeql-owner-null-state-observation.json)،
وتأكد أن [مخطط GitHub REST الرسمي](evidence/github-codeql-null-state-schema.json)
يعرف `code-scanning-alert-state` بأنه nullable. تسجل نسخة المخطط المصدر وSHA256
للملف الرسمي الذي استُخرجت منه التعريفات.

## السلوك الحالي

- تُراجع هوية التنبيه والقاعدة والأداة أولًا. تبقى الحالة الغريبة أو حقل الحالة
  المفقود مانعًا؛ وجود null الصريح وحده لا يثبت أن التنبيه مفتوح.
- عند الحالة العامة null، يلزم وجود instance صريحة `open` على PR29، مع فحص
  موقعها ومصدرها الكامل. إذا كانت جميع instances الخاصة بالطلب مغلقة صراحةً،
  تُسجل «already closed on reviewed PR» دون كتابة.
- تبقى جميع النسخ المفتوحة خاضعة للتحقق. وأي instance بحالة فارغة في ref آخر
  تُفحص كنسخة قد تكون نشطة، فلا يُسقطها مرشح الحالات بصمت.
- تبقى مراجعة المصدر الحالية إلزامية على PR29. وتُقبل على refs الأخرى النسخ
  التي سبق أن روجعت، بموقعها وhash ملفها والقاعدة والقرار أنفسهم، كما في متابعة النسخ.
- تظل الدفعة كلها مطالبة باجتياز preflight، ثم تعاد قراءة instances والرؤوس قبل
  كل PATCH. طلب الإغلاق نفسه يرسل `state: dismissed` وفق API، ولا يرسل null.
- إذا رد PATCH بحالة عامة null، لا تُسجل العملية ناجحة إلا بعد قراءة جديدة
  تؤكد `dismissed` لكل snapshot كان نشطًا ومراجعًا. غياب نسخة أو بقاؤها مفتوحة
  أو فارغة يوقف الدفعة، مع `unconfirmed_patch.patch_sent: true` لتمييز الطلب
  الذي أُرسل عن الحالات التي لم تصل إلى الكتابة. الحالة العامة وحدها لا تكفي.

يقدم التقرير كذلك `blocked_alert` للفرق في رقم التنبيه أو القاعدة أو الأداة
أو الحالة، و`blocked_instance` للمصدر أو حالة النسخة، دون تغيير بوابة CheckRun.

## التحقق وحدوده

أعيد إنتاج العطل قبل الإصلاح باستخدام بيانات #243 الفعلية: فشلت ثلاثة اختبارات
وأخفق اختباران من 32. بعد الإصلاح مرت **50 تجربة محاكاة**، منها 37 لأداة PR29
و13 للدفعة التاريخية. تشمل الدفعة التجريبية الأرقام والحالات العامة الـ11 التي
أرسلها المالك، ثم اختبار إعادة التشغيل مع بقاء الحالات العامة الست null، واختبار
إرسال PATCH دون تأكيده ومنع الكتابات اللاحقة. السجلان:
[قبل](evidence/codeql-null-state-before.log) و[بعد](evidence/codeql-owner-helpers-50-tests.log).

تُستعمل instance #243 الملتقطة من GitHub كما أرسلها المالك. أما instances
الحالات الأخرى وردود PATCH في هذه الاختبارات فنماذج خدمة، بمصادر النسخ التي
سبق أن روجعت، وليست ادعاءً بحدوث إغلاق فعلي. لا تزال النتيجة الفعلية تحتاج
جلسة المالك بسبب منع التكامل من واجهات code-scanning المحمية بـ403.

من مجلد المالك الحالي:

```powershell

```

نفسها قبل الدمج؛ لا تغير هذه المتابعة مصادر المنتج أو نتائج CI السابقة.
