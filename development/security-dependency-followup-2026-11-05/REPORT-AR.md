# متابعة الاعتمادات — 5 نوفمبر 2026

عولج محليًا اعتماد `tmp` في أدوات مترجم Solidity: انتقل من **0.0.33 إلى 0.2.7** مع إبقاء **solc 0.8.28**. أصبح فحص npm لهذه الأدوات صفر تنبيهات، ونجحت اختبارات احتواء المسارات، وتطابقت مخرجات العقود الـ13 بايتًا. **ما زال اعتماد التشفير القديم في مسار EVM العام يحتاج معالجة منفصلة؛ التدقيق الكامل لم ينتهِ، ولم تُرفع هذه الدفعة أو تُدمج أو تُنشر.**

## تنبيها tmp والتغيير

كشف [فحص npm قبل التغيير](evidence/npm-audit-before.json) تنبيهين أصليين في `tmp`:

| التنبيه | الشرط والإصدارات المتأثرة بحسب التقرير |
| --- | --- |
| [GHSA-52f5-9888-hmc6](https://github.com/advisories/GHSA-52f5-9888-hmc6)، مصنّف low | الكتابة عبر `dir` يشير برابط رمزي إلى خارج جذر الملفات المؤقتة؛ `<=0.2.3`. |
| [GHSA-ph9p-34f9-6g65](https://github.com/advisories/GHSA-ph9p-34f9-6g65)، مصنّف high | خروج من المجلد عبر `prefix` أو `postfix` غير المنقّيين؛ `<0.2.6`. |

عدّ npm حزمتين متأثرتين: `tmp` و`solc` بوصفه مستهلكًا لها. لا يعني ذلك ثغرتين مستقلتين داخل المترجم بالإضافة إلى تنبيهي tmp.

أضيف override محدد تحت `solc` إلى [package.json](../../prototypes/lp4-execution/tools/package.json)، وحُدّث [القفل](../../prototypes/lp4-execution/tools/package-lock.json). اختير `tmp 0.2.7`، الذي يشمل إصلاحات احتواء المسارات والتحقق من نوع خيارات الاسم. أزيل `os-tmpdir 1.0.2` الذي لم يعد مطلوبًا. **كل سجل حزمة آخر في القفل بقي مطابقًا بالكامل**، بما فيه solc وfollow-redirects؛ لم يُستخدم `npm audit fix` أو تُعطّل قاعدة فحص. [فرق القفل المحصور](evidence/npm-lock-changes.json).

تحققت مطابقة integrity مع بيانات سجل npm الرسمي، ونجح تثبيت نظيف بالقفل قبل التغيير وبعده مع تعطيل install scripts. كذلك تأكد أن `require` من داخل solc نفسه يحل `tmp` إلى 0.2.7؛ ليس الاستنتاج مبنيًا على قراءة القفل فقط. [الإصدار](evidence/selected-tmp-release.json)، [الحل الفعلي](evidence/resolved-tools.json).

هذا تحديث لأدوات البناء. يستدعي solc الحزمة في مساعد SMT عبر `fileSync({postfix: '.smt2'})` بقيمة ثابتة، ثم `removeCallback()`. لم نجد في مسار بناء fixtures المختبر تمرير prefix أو postfix أو dir من مستخدم غير موثوق. أثبت الاختبار خلل المكتبة القديمة ضمن ظروفه، **ولم يثبت استغلالًا في بناء المشروع المعتاد أو في خدمة إنتاج**.

`9ef37cc1d2597ed6d2f706a960f449e33eb9eee920936cea77b11e6f43861970`

أُعيد تشغيل كل ملفات `compile_*.cjs` الاثني عشر، إضافة إلى حالة system-v1 مع `--continuous`، على التثبيتين المقفولين. **المخرجات الـ13 متطابقة بايتًا**، وتطابق أيضًا بصمات الجولة المقبولة السابقة. تشمل المخرجات ABI والبايت كود وبيانات التخزين والإعدادات والتحذيرات التي تكتبها أدوات fixtures، وليس طول البايت كود فقط. [المقارنة](evidence/compiler-comparison.json)، [حزام المقارنة](compare_compilers.py).

لم يُعدّل fixture متتبع أو مصدر عقد أو إصدار مترجم. بقيت مصادر Rust وأقفالها مطابقة للأساس المختبر، وطابقت كل بصمة مصدر في بيان البناء السابق الملفات الحالية. لذلك لم تُكرر مجموعتا Rust أو بناء Android الناجحتان من الجولة السابقة لمجرد تغيير أدوات Node. بقيت بصمة مصدر العقدة:

`57cc150e7d57023f750b94f8cfd8d5a1552f3297079f9dba3f8db6ceb54796e8`

يحتاج override إلى npm 8.3 أو أحدث، وترفع الحزمة الجديدة حد Node إلى 14.14 على الأقل؛ يحتاج حزام `node:test` إلى 18 أو أحدث. نُفذ التحقق على **Node 24.22.1 / npm 11.9.0 / Linux**. اختبار العملية المصطنعة يستخدم اقتباس POSIX ويُتجاوز صراحة على Windows؛ لم يُثبت تحقق Windows أصليًا.

## لماذا بقي تنبيه التشفير في EVM؟

الإصلاح السابق في `e3d6ae4ae15554e0ed60446e13d1b71585edde44` ينقل عمليات المفاتيح الخاصة إلى سلسلة مصححة. لكن [رسم الاعتمادات الفعلي](evidence/evm-legacy-dependency-tree.log) يثبت أن `crypto-bigint 0.5.5` يأتي أيضًا عبر:

- `revm-precompile 16.2.0 → k256 ^0.13.3`، باعتماد غير اختياري حتى عند استخدام backend الخاص بـsecp256k1.
- `revm-primitives 15.2.0 → alloy-eip7702 ^0.5` مع تفعيل k256 صراحة.
- `alloy-eip7702 0.5.1` و`alloy-primitives 0.8.26` اللذين يطلبان k256 ^0.13، ثم elliptic-curve ^0.13 وcrypto-bigint ^0.5.

راجعت بيانات الإصدارات الرسمية؛ آخر إصدارات العائلات المتوافقة القائمة هي 16.2.0 و0.5.1 و0.8.26، وتحتفظ بهذه القيود. تحديث k256 المباشر وحده لا يزيل الاعتماد من EVM، ولا يحل `[patch]` إلى 0.7 عدم توافق قيود 0.5 وواجهاتها. [التقييم والقيود والبصمات](evidence/evm-assessment.json).

لم تُجر ترقية كبيرة لـEVM أو fork محلي للاعتمادات بهدف إزالة التنبيه. يلزم لترحيلها عمل مستقل يقارن نتائج Cancun والغاز والأخطاء والسجلات وجذور الحالة والإيصالات، وحدود الاستعادة العامة والتواقيع غير الصالحة، وEIP-7702 وتفعيل الفروع، وخطافات PAY وfixtures النظام والبناء الأصلي. هذه مقارنة مطلوبة لاحقًا، ولم تُدّع نتائجها هنا. بقي التنبيه ظاهرًا في فحص Rust السابق؛ **صفر تنبيهات npm لا يشمل هذا الخطر أو الديون الأخرى**.
