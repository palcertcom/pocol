## نتائج الأدوات والمقارنة

### Semgrep

شمل جرد الفحص الأول في هذه الجولة **767 مسار شيفرة/markup**، بحجم 27,724,609 بايتًا، وحُفظت نسخ بايتية مطابقة في **735 snapshot مختلفة** خارج تسميات dist/assets/الأدلة لتفادي إهمالها الافتراضي. لا حد حجم يستبعد soljson.js أو حزم IDE. الجرد الحالي بعد إضافة أدوات التحقق **772 مسارًا**؛ الخرائط والتجزئات تحفظ الفرق. رقم الملفات المختارة ليس دليل تحليل دلالي لكل لغة أو كل سطر.

باستعمال Semgrep OSS `1.183.0` وقواعد المصدر عند `16b9e6d45f10649f6a531ec4838ed9924372c3bc`، شغّل الفحص الموسع 368 قاعدة، وأنتج **637 ملاحظة و26 خطأ تحليل/مطابقة/مهلة**. تصنيف الأداة 308 ERROR و102 WARNING و227 INFO لا يساوي تصنيف خطورة نهائيًا. [البيانات الخام المضغوطة](evidence/round2/semgrep-wide.json.gz)، [الملخص](evidence/round2/scan-summary.json).

السجل [668 صفًا بحسب التشغيل](ROUND2-SEMGREP-TRIAGE.md) و[أسبابه بالعربية](ROUND2-SEMGREP-TRIAGE.json) يحفظ كل نتيجة من التشغيل الموسع وإعادة الحزم وworkflows والتغييرات النهائية. تتكرر المواضع بين هذه التشغيلات؛ ليست 668 ثغرة. أمكن ربط 313 ملاحظة في التشغيل الموسع بمراجعة الجولة الأولى؛ بقي تصنيف 91 ملاحظة تاريخية تصنيف سياق، لا إعادة تشغيل لكل شاهد. تُفصل sinks غير المحسومة عن النصائح الغازية وعن أدوات الاختبار. لم تُضف suppressions أو يُحذف ملف لتحسين النتيجة.

لتحسين تحليل الحزم، نُسقت نسخ من الملفات الخمسة بواسطة Prettier 3.6.2، وأعيد تحليل الأصل والناتج بواسطة Babel 7.28.5. تطابقت تجزئة AST بعد إزالة metadata المواقع/التعليقات/الكتابة الخام؛ [الخريطة](evidence/round2/format-map.json). لم تتغير ملفات التوزيع. هذا أتاح نتائج إضافية، لكنه **لم يحل فجوة التغطية**: التشغيل أنتج 20 ملاحظة، و56 مهلة لقاعدة/ملف في حزمتَي IDE الكبيرتين، وpartial parsing في editor worker. الملاحظات الأربع في Explorer هي sinks داخل React، وتحتاج متابعة تدفقات المدخلات؛ ليست إثبات XSS. ضبط الـallowlist في sandbox worker اختُبر أيضًا فعليًا برفض `constructor`.

أعيد فحص workflows بأسمائها الأصلية للـrules المقيدة بالمسار: 3 ملاحظات mutable tags، و20 مشكلة مطابقة/تحليل، أغلبها مقاطع PowerShell التي تحللها قواعد bash. لم تُستبدل أدوات التنفيذ أو تُفعّل جدولة. بقي C JNI جزئي التحليل في Semgrep؛ يعوض جزءًا من ذلك GCC `-fanalyzer` وJVM ذي checked JNI والبناء الحقيقي، لا ضمان سلامة مطلق.

في مقارنة مركزة للمصدرين المعدلين، أظهر main ملاحظتي Python وpartial parsing في C؛ بقيتا بعد الإصلاح. أظهر فحص الرقعة ذات 10 ملفات 8 ملاحظات (منها أدوات الاختبار) وخطأ C الجزئي. وبعد إصلاح F5 أعيد فحص ملفَي الصنبور المعدلين: الملاحظتان نفسيهما، وصفر أخطاء تحليل؛ [السجل](evidence/round2/semgrep-faucet-snapshot.log). **الأداة لم تكشف أصل أخطاء الموارد والترميز**؛ دليل الإصلاح هو اختبارات قبل/بعد، وليس تحول عدد Semgrep إلى صفر. لا تقارن 637 بنتائج الجولة الأولى أو الـ67 الأصلية مع اختلاف النطاق والقواعد. artifact الأصلي ما زال غير متاح، فلا ادعاء بمراجعة نتائجه واحدة واحدة.

### التبعيات وCodeQL

تظل مراجعة RustSec/npm وتطبيقية follow-redirects وtmp وkeccak وrand والصيانة والإصدارات المسحوبة كما فُصلت في [الجولة الأولى](REPORT-AR.md). لا تحديث اعتماد إنتاجي جديد في هذه الجولة. lockfile الـfuzz منفصل ويضيف أدوات الاختبار، ولا يستبدل أقفال التطبيق.

**crypto-bigint 0.5.5 / RUSTSEC-2026-0387 يبقى خطر توقيت غير محسوم** في شجرة k256. لم يثبت استغلال محلي ولم يثبت عدم الانطباق؛ لم يُرقّ إلى فرع 0.7 قسرًا أو تتغير مكتبات التشفير لتصفير الفحص. يحتاج تقييم عمليات الأسرار والمترجم/المعمارية وحلًا متوافقًا مع شجرة الاعتماد واختبارات التوافق. تنبيهات tmp بقيت أيضًا؛ المعطيات الحالية لا تثبت تشغيل شروط استغلاله في بناء fixtures المثبّت.

لم يُنزّل تقرير OSV الأصلي أو Semgrep الأصلي بسبب رفض API؛ تنزيل release من github.com نجح، وهذا لا يمنح الوصول إلى api.github.com. PR24 الخاص بـTLS، رأسه الذي روجع `c690f990c619214d1e75354208f32580b17b4544`، خارج main في المرجع المفحوص. بقي اختبار مصدره/مولّده ناجحًا كما في الجولة الأولى، لكن **إغلاق CodeQL #7 وأحدث CI وحالة الدمج الحالية لم تُتحقق عبر API**. لم تُعتبر PR26/27/28 مدموجة أو تُفعّل فحوصها المجدولة.

### كشف الأسرار

فُحصت أولًا نسخ الشيفرة الـ735 بلا verification شبكي (115 مرشحًا). ثم أُجري فحص مستقل لكل الملفات المتتبعة وقت بدايته: **5,953/5,953**، بوظيفتَي عمل ومهلة 5 ثوان لكل ملف، وصفر مهلات؛ كشف الضابط الإيجابي 5 matches. أُهملت inline allowlists في هذه الإعادة بدل اعتمادها لإخفاء نتائج. [الأداة](tools/scan_secrets_bounded.py)، [الملخص والإعدادات](evidence/round2/secrets-summary.json)، [سجلات hashes فقط](evidence/round2/secrets-bounded.jsonl.gz).

النتيجة **29,258 مرشحًا في 811 ملفًا**: 29,049 hex entropy، و182 base64، و17 keyword، و6 basic-auth، و3 AWS، و1 Telegram. معظم الحجم قيم تجزئة وبراهين واختبارات تاريخية. السياقات المميزة تشمل كلمات المرور الاصطناعية ورسائل سياسة كلمة المرور وURLs التي تختبر الرفض؛ أنماط AWS داخل base64 لـWASM، ونمط Telegram هو `artifact-ID:hash` في توثيق. لم تثبت هذه المراجعة تسريب credential قابل للاستعمال، ولم تُختبر أي قيمة على خدمة. **لم يُحسم كل مرشح عالي entropy يدويًا**، ولا يتناول هذا فحص كل أسرار تاريخ Git أو إعدادات المضيف غير المتتبعة.

محاولة CLI غير المقيدة سبقت الإعادة وأوقفت بعد دقائق دون JSON مكتمل؛ لا تُحسب نجاحًا أو نتيجة صفرية. كانت محاولتان أقدم خارج جذر Git تعددان صفر ملفات؛ رُفضتا كدليل، وفُحص الضابط الإيجابي وتعداد الملفات قبل اعتماد النتائج.

## العوائق والمتبقي

- سياسة `/etc/chromium/policies/managed/extensions.json` تحوي `ExtensionInstallBlocklist:["*"]`، وCDP أعاد `Loading of unpacked extensions is disabled by the administrator.`. [الملاحظة](evidence/round2/browser-policy-observation.json). لم تُعدّل السياسة أو يُبدّل المتصفح للالتفاف عليها. يلزم منفذ اختبار يسمح به المسؤول لتشغيل الإضافة، إضافة إلى متصفح Playwright المطابق الذي تعذر تنزيله سابقًا.
- `api.github.com` ما زال خارج الشبكة المفروضة. Git read/push وrelease download يعملان، بينما تنزيل artifacts/CodeQL/CI وإنشاء PR عبر API محجوبة. محاولة PR المسجلة في الجولة الأولى فشلت بـForbidden؛ لا يُقدَّم رابط بدء الإنشاء بوصفه PR منشأ. [الوصف الجاهز](PULL_REQUEST.md)، [بدء إنشاء PR](https://github.com/palcertcom/pocol/pull/new/security/audit-2026-11-04).
- تبقى متابعة crypto-bigint وtmp والصيانة/الإصدارات المسحوبة، وتدفقات DOM والمهل في الحزم الكبيرة، وWindows وART/الأجهزة، واختبارات العزل الكاملة وقياسات الأسوأ والانقطاع الحقيقي. لا تُغلق بإتمام هذه الجولة.
- مخرجات الأدوات المحلية ليست artifacts OSV/Semgrep الأصلية. لم تُراجع ملاحظاتها الأصلية بأرقامها، ولم يُثبت إغلاق CodeQL #7 أو دمج PR24.

حُدّث `start_skill` في مسودة إعداد البيئة بمسارات الأدوات والاختبارات وسبب منع الإضافة؛ حُفظت متطلبات الشبكة السابقة. حفظ المسودة لا يطبقها أو ينشرها. يلزم ضبط الوصول إلى API وبيئة اختبار إضافات مسموحة من إعدادات البيئة/المسؤول لاستكمال الأجزاء المحجوبة، دون طلب أسرار في المحادثة أو تجاوز السياسة.
