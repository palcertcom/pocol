## النتيجة وأساس القرار

القيم هي عدادات الحساب العامة التي تدخل في اشتقاق عنوان عقد Ethereum:
`keccak256(rlp([sender, nonce]))[12:]`. الدليل المباشر هو تنفيذ
[`Address::create`](../../prototypes/third-party/evm-crypto/alloy-primitives-0.8.26/src/bits/address.rs#L350).
يستقبل `u64`، يرمّز المرسل العام والعداد بـRLP، ثم يحسب العنوان بـKeccak.

راجعنا أيضًا [`Key::address` و`Key::sign_hash` و`Tx::sign_1559`](../../prototypes/lp4-execution/src/txsign.rs):
عداد المعاملة يُسلسل ضمن رسالتها العامة، والتوقيع يتلقى digest عبر واجهة
RFC6979. القيم المشار إليها هنا ليست قيمة nonce السرية للتوقيع أو مفتاحًا أو IV.
القرار لكل التنبيهات الـ19 هو `false positive` بناء على هذه الدلالة، لا على
وسم الاختبار وحده. تثبيت العدادات مطلوب لإعادة حساب عناوين العقود ونتائج الاختبارات.

## التنفيذ وإحصاء المفتوح بعده

### تصحيح حد تعليق GitHub واستئناف محاولة HTTP 422

أكّد تقرير المالك إغلاق 236، ثم رفض GitHub تعليق 237: كان 287 حرفًا بينما
حد API هو **280**. كان افتراض الحد 512 في الحراسة خطأ. صُحح الحد المشترك في
أدوات الدفعة التاريخية وPR29 والدفعة الحالية، ويُفحص كل تعليق قبل أول اتصال
شبكي للدفعة، وكذلك عند الطلب نفسه. لا تقطع الأداة التعليقات تلقائيًا.

أصبح تعليق 237 المراجَع 212 حرفًا، وأطول تعليق في خطة الـ19 هو 276 حرفًا.
تغيّر نص هذا التعليق وبصمة الخطة فقط؛ بقيت المعرّفات والمواقع وبصمات المصدر
وقرارات `false positive` كما هي. خطتا الـ197 وPR29 وملفات المنتج لم تتغير.
الاستئناف يتخطّى 236 عندما يكون مغلقًا ويعيد التحقق من بقية الدفعة.

الخطة مستقلة عن خطة الـ197 السابقة. الأداة الجديدة تستدعي حراسة التطبيق
المشتركة التي اجتازت اختبارات PR33: تحقق كامل قبل أول PATCH، وفحص المصدر
الحالي على main وكل نسخة مفتوحة، وإعادة قراءة البيانات وثبات HEAD قبل كل إغلاق.
الحالات الفارغة أو غير المعروفة والتغييرات غير المراجعة توقف الدفعة قبل الكتابة.

من جذر المستودع، باستخدام جلسة `gh` الحالية ذات صلاحية CodeQL:

```powershell
python development/security-codeql-remaining-2026-11-07/apply_remaining_codeql.py --apply --out codeql-remaining-19-apply-v2-2026-11-07.json
```

الاسم يجب أن يكون جديدًا. بدون `--apply` تعمل الأداة للقراءة فقط. لا تطلب رمزًا
أو تسجيل دخول جديدًا؛ وصول التكامل السحابي إلى CodeQL مرفوض، لذا التنفيذ الحقيقي
يستخدم حساب المالك المعتاد.

بعد التطبيق، تستعلم الأداة **للقراءة فقط عن كل المفتوح على main**، بما يشمل
الأدوات والقواعد والمعرّفات غير الموجودة في هذه الخطة. تحفظه في التقرير نفسه؛
لا تُغلق أي صف خارج الخطة. النتيجة التي تثبت خلو main وقت الفحص هي اجتماع:

- `phase: complete` و`application_complete: true`.
- `postcheck_stable_main: true`.
- `remaining_open_main_count: 0` و`main_clear_at_postcheck: true`.

إذا فشل الاستعلام النهائي أو تغيّر main، تحتفظ الأداة بالإغلاقات المؤكدة ومرحلة
`postcheck`، ولا تسجل ادعاء خلو main. وإذا أُعيدت تنبيهات أخرى، تُحفظ كلها
للمراجعة. يمكن إعادة التشغيل باسم تقرير جديد؛ المعرفات المغلقة تتخطاها الحراسة.
