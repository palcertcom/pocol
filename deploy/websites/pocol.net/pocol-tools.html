Wallet and developer tools

PoCol brings together native Windows and Android wallets, a Linux node and command-line tools, PoCol Studio, and the Chrome publishing and viewing extension. The available applications connect to the PoCol Mainnet; the repository also supports local development networks.

Download the native applications

The network upgrade is active from block 15000. Use the complete 0.4.0 native package with the matching public network file. Chrome extension users must save the trusted schedule [[1,"0"],[2,"15000"]] in Options → PoCol Mainnet activation and reopen Viewer tabs.

Choose the package for your device. These applications connect to PoCol Mainnet; the implementation remains experimental. PCOL is the currency symbol and PoCol is the network name. The Windows and Android wallets run the validating node engine and sign transactions locally. Mining starts disabled and requires an eligible identity before you enable it.

  • Windows 10 22H2 / Windows 11, x64: download the complete PoCol-Mainnet-0.4.0-Windows.zip and the separate public network.pocol.json. Keep all executables together. On a new wallet home, import the public network file. Preserve the existing Windows account and wallet home when updating.
  • The Android update is being prepared with release signing. A compatible download will be published when ready. Keep your existing application and wallet data. The signed Android update is pending; an APK signed with another key cannot update the existing installation.
  • Linux x86_64: the archive contains a full node and command-line tools. It does not include a graphical wallet. Read its installation guide before setting up a new node, and preserve existing keys and state. Desktop users may run install-desktop-icon.sh as their ordinary user to add the supplied icon and an informational menu shortcut. It does not start or reconfigure the node; headless servers can skip it.
  • iOS, iPadOS and macOS: no native application release is available in this distribution.

A wallet with separate approvals

The PoCol extension includes an embedded development wallet as well as the Studio publishing workflow. Creating or unlocking a wallet, granting a website access and approving a transaction are separate actions. A site cannot treat a connection permission as blanket permission to sign future transactions.

The extension displays the exact signing payload and its hash before signing. It supports EIP-1559 transactions and rechecks network identity and session eligibility. Locking the wallet or changing the profile cancels pending approvals, preventing an old request from carrying on under a new context.

Wallet keys and device data

The browser extension’s development wallet encrypts its seed with AES-GCM and a password-derived key using PBKDF2-SHA256 with 600,000 iterations. HKDF derives a key for each network identity. It auto-locks after 15 minutes without a qualifying user action; unlocking it or approving access or a signature refreshes that timer. These are implementation properties, not a substitute for an independent security audit.

Back up the wallet home, close the wallet and extract the complete 0.4.0 package. Download the current public network file and place it beside the application. Use Settings → Upgrade existing network while disconnected. Preserve the same Windows account and wallet home. If the stored history has already reached block 15000, retain all data and obtain migration support before proceeding.

Android updates must use the same signing certificate as the installed application. A new debug build may have a different certificate. Do not uninstall a wallet-bearing application to bypass a mismatch: uninstalling deletes its identity and local state. Durable Android updates require an operator-retained release signing key.

PoCol Mainnet is the public network name; it does not imply completed production qualification. The repository’s deterministic local-devnet accounts are public test identities and must never protect real assets.

Tools for each part of the workflow

Start with the current README and record the exact repository commit. The walkthrough builds the node and extension, initializes a three-node local simnet, checks that block heights advance, publishes a small site and verifies it from another synchronized node.

Keep a devnet’s generated directory if you want to stop and resume it. The documented workflow separates initialization from starting existing nodes, so you can preserve the chain and published sites between sessions. Check network identity and synchronization before comparing results across nodes.

  • pocold: run the node, execute transactions, synchronize peers and mine blocks.
  • pocol-site: publish a static site and fetch its contents with verification.
  • pocol-sign: command-line signing tools for the development workflow.
  • PoCol-specific RPC: inspect templates, nonce assignments, miners, rewards, synchronization and diagnostics.

Contribute with reproducible evidence

Useful contributions include reproducing a documented issue, improving an explanation or adding a focused boundary test. Keep the tested commit, commands and results together. Consensus-rule changes require the project's explicit decision process; a proposed feature is not an implemented guarantee.

The repository demonstrates local development functionality, while production admission, open security questions and independent audit remain separate work. Explore the source and the project-status page before choosing what to build or deploy.
