Websites on PoCol

Design a page in PoCol Studio, publish its files to the PoCol Mainnet with the Chrome extension, and open a version whose contents are checked before display.

The files themselves are stored

The experimental storage design keeps website bytes in contract code, not merely a link to an external server. The publisher splits files into chunks and deploys them through ChunkFactory. CREATE2 derives each chunk address from its contents; an existing matching chunk can be reused.

A manifest describes each file's path, type, size, content hash and chunks. HTML, CSS and JavaScript are supported, together with JSON, common image formats, WOFF2 fonts and text. The viewer reconstructs the files and checks their hashes before rendering them.

Create and publish with PoCol Studio

PoCol Studio is a browser editor for static websites. Start with a personal, business or product template, or import a folder containing index.html and its HTML, CSS, JavaScript and supported assets. Templates begin in English; you can choose Arabic for the page and switch the editor interface separately.

Drafts stay in the current browser. Save a project backup before moving devices or clearing browser data. Designing or saving a draft does not publish anything; transactions begin only after approval inside the extension.

  • 1. Install PoCol Studio & Viewer in Chrome, then reload Studio so it can detect the extension.
  • 2. Open studio.pocol.net, create a project and edit its text, colors, logo and sections. Check the desktop and mobile previews.
  • 3. Select Publish to PoCol, review the file summary and continue to the extension. Create or unlock a publishing wallet, or import an encrypted export of your existing Windows wallet in the extension confirmation tab.
  • 4. Check the wallet, files and maximum fee. You need enough PCOL balance for the displayed fee cap. Approve the request and select Confirm & publish.
  • 5. Keep the extension tab open until completion, then open the website and save its contract address. Avoid sending other transactions from the same wallet while publication is active.

One address, multiple versions

The Website contract keeps a version history and a pointer to the current published version. An update creates a new version; selecting a previous published version provides a rollback without changing the site's address. Draft, published and revoked states distinguish the lifecycle of each version.

The owner manages publishing permissions and can transfer ownership in two steps. The contract supports up to 16 publishers and 1,024 versions. Revoking a version does not erase its historical bytes from the network.

In Studio, use Publish update from the saved project to keep the same site address. You can also link a draft containing your files to an existing site address. The extension checks that the wallet is authorized to publish to that contract before signing; a new unrelated wallet cannot update someone else’s site.

Build for the current limits

The current viewer allows at most 4 MiB per site, 256 files, 1 MiB per file and a 64 KiB manifest. Each chunk carries at most 24,575 bytes. Publishing requires transactions and gas; storage is not free or unlimited.

These are static website files, not server-side PHP or Node.js hosting. Applications can interact with contracts through the extension's controlled bridge. Browser localStorage stays on the visitor's device. The current model is experimental and does not promise permanent public hosting.

The Studio import preview does not execute JavaScript or make external requests. Published files remain unchanged, so test the finished page in the extension viewer. If a publication is interrupted, reopen its existing job from the extension’s Publication history and resume it.
