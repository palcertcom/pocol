The Chrome extension

PoCol Studio & Viewer 0.4.1 connects Studio publishing and IDE contract transactions to wallet approval on your device. It also opens on-chain websites in an isolated viewer. Wallet unlock and signing happen inside the extension.

Install the Chrome extension

This development release supports Chrome 130 or later and is installed from a ZIP using Developer mode. It has not been published in the Chrome Web Store. Select the extracted folder that contains manifest.json.

  • Download PoCol-Studio-IDE-Viewer-0.4.1.zip and extract it to a folder you will keep.
  • Open chrome://extensions in Chrome and turn on Developer mode.
  • Select Load unpacked and choose the extracted folder containing manifest.json.
  • Open or reload studio.pocol.net or ide.pocol.net after installation. The built-in Mainnet profile connects through the PoCol HTTPS gateway; this workflow does not require a local node or an SSH tunnel.
  • For an existing installation, replace the files in the same extension folder and select Reload, then refresh the IDE. Keep the existing extension installation to retain its wallet storage.

Approve publication in the extension

Studio sends the public website files to a dedicated extension confirmation tab. Review the account, file list and maximum fee there. No publishing transaction is signed until you unlock the wallet, select the approval checkbox and confirm. Keep this tab open until the publication finishes.

To use an existing Windows wallet, run tools/Export-Studio-Wallet.ps1 from the extension package under the Windows account that owns the wallet. Choose an export password of at least 10 characters. The script creates the encrypted PoCol-Studio-Wallet.json on the desktop. Select that JSON only inside the extension confirmation tab and enter its password there. Never upload the wallet file or private key to Studio.

The publishing wallet is stored encrypted in the extension; decrypted key bytes remain in the trusted confirmation tab and lock after 15 minutes or when that tab closes. To update an existing site, use a wallet authorized by its Website contract.

The native currency symbol is PCOL. The publication fee cap is displayed in PCOL; PoCol is the name of the network and its products.

Deploy and interact from PoCol IDE

Choose PoCol Mainnet in the IDE and use PoCol wallet to send a deployment or contract-write request to the extension. Review the transaction and PCOL fee cap in its confirmation tab, unlock your wallet and approve. Connecting or unlocking the wallet alone does not approve the transaction.

The extension includes tools/Export-Studio-Wallet.ps1 for Windows and tools/export-studio-wallet.py for Linux. Follow the included instructions to create an encrypted wallet export on your device. Import and unlock it only in the extension wallet tab. The IDE never asks for your private key or wallet password.

Checks before display

The extension checks the endpoint's chain ID and genesis hash against the selected profile. It reads the site's current version, fetches manifest and file chunks, verifies the CREATE2 address of every chunk and compares the manifest and file hashes. Invalid content is rejected instead of being displayed as verified.

Content integrity and chain trust are separate. A correct file hash does not by itself prove that the endpoint supplied the canonical state. The trust banner outside the website frame explains the selected verification mode.

Understand the trust mode

The built-in public profile uses RN mode: it trusts the remote PoCol node for execution while checking the pinned network identity and website file hashes. Its banner says “remote PoCol node trusted; file hashes verified.” This does not claim independent verification of every block’s execution.

LN relies on a trusted local node for full execution verification. RP checks network identity and a limited window of at most 13 headers; it does not verify complete execution or miner membership. DEV is explicitly a development mode without that verification. The interface keeps these distinctions visible.

A controlled application environment

Websites run inside a sandbox with a restrictive content policy, per-tab network rules and WebRTC restrictions. Their requests pass through BridgeAuth, which checks allowed methods, message structure and resource limits. Wallet confirmations appear outside the site's frame, so the page does not control the approval interface.

Remote access is restricted to the pinned PoCol HTTPS gateway in RN mode. Existing loopback-node profiles remain available for local development. The extension is experimental and its isolated viewer is not a replacement for unrestricted web browsing.

Plan for this environment when authoring a site: bundle dependencies, keep navigation within published paths and use the permitted bridge for contract interaction. A page that expects arbitrary external APIs, embedded third-party frames or remote scripts will not behave like an unrestricted conventional website.

Update or resume an existing installation

If you already loaded the extension from a folder, close publishing tabs before updating. Replace the files in that same folder with the contents of the new extension folder, then choose Reload on its card at chrome://extensions. Keeping the same installation folder preserves the extension identity and stored data. Reload Studio afterwards.

After an interruption, use Publication history in the extension options to reopen the existing operation and approve resuming it. Keep the same wallet and do not start duplicate publications while a signed transaction is unresolved.
