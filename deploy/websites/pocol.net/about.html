A shared approach to proof of work

PoCol — Proof of Collaboration — organizes miners around a common block template and separate search ranges. Its experimental implementation brings coordinated mining, smart contracts and verifiable website publishing into one research platform.

One template. Distinct contributions.

PoCol keeps the hash-target puzzle of proof of work and selects chains by cumulative work. It changes how a mining round is organized: eligible miners work on a canonical template, while a deterministic assignment divides its nonce space into non-overlapping ranges. Under the common-template and honest-assignment assumptions, honest miners do not repeat the same candidate-header input within that round.

Collaboration is expressed through verifiable shares as well as the winning solution. The protocol records those contributions and applies explicit settlement rules. A share samples work; it does not certify that a miner searched every possible value in its range.

From consensus to applications

The repository extends the original consensus idea into a working development stack. Its Rust node, pocold, handles mining, peer communication, validation, persistence and JSON-RPC. An EVM execution layer uses revm with Cancun rules, allowing contract execution alongside PoCol's own consensus process.

Together, these components let developers explore an application whose contract logic and published interface are both connected to the chain. Content has an address and a version, and the browser can check whether the fetched bytes match the published manifest. This is a development capability, not a promise of permanent storage or unrestricted web compatibility.

  • Coordinated mining assigns distinct work to eligible identities.
  • System contracts manage contribution records, reward settlement and network limits.
  • Website contracts track versions and manifests; chunk contracts store the content bytes on-chain.
  • A Chrome extension verifies website bytes before rendering them in an isolated frame.

A research foundation

PoCol was conceived by Raed S. Rasheed and studied in his doctoral research. The thesis evaluated mining policies through BlockSim simulations with energy modelling. The EVM layer, website storage and browser extension are later implementation additions, so simulation results should not be read as benchmarks of the Rust node.

The useful distinction is between implemented mechanisms and proven guarantees. The code demonstrates local development networks and application flows. Production readiness, PoW-equivalent security, fairness and Sybil resistance are not established. Explore the implementation, inspect its sources and read the status page alongside the feature descriptions.
